# PRD：面向 LLM Agent 训练的「代码优化+正确性约束」任务数据合成 Pipeline

## 1. 文档信息
- **版本**：v0.1
- **状态**：Draft
- **作者**：Codex Agent
- **目标读者**：数据工程、评测工程、训练工程、Agent 平台研发

---

## 2. 背景与问题定义
给定参考任务具备如下特征：
1. 目标函数已有半成品实现，需要在限定入口中补全；
2. 同时存在**正确性约束**（例如数值关系/等式验证）与**性能约束**（对参考实现有速度优势）；
3. 需要 Agent 执行完整工程闭环：读代码、改实现、运行评测脚本、迭代优化。

该类任务可用于训练 Agent 的复合能力，但直接围绕同一问题（如特定线代计算）扩充样本，会产生高相似度与基准污染风险。

本 PRD 定义一个**任务合成 Pipeline**，输出仅包含：
- 训练指令（Instruction）
- 验证方案（Validation Spec）

不输出标准答案代码，以便用于 Agent 训练或在线对战评测。

---

## 3. 产品目标（Goals）
### 3.1 主要目标
1. 生成与参考任务**能力等价**但**语义不同**的数据样本；
2. 覆盖“正确性 + 性能 + 工程约束”三重目标；
3. 可自动批量生成、自动去重、自动难度分层；
4. 每个样本都具备可执行验证方案（正确性、鲁棒性、性能、资源约束）；
5. 可直接对接 Agent 训练框架（SFT、DPO、RL、self-play）。

### 3.2 成功指标（KPI）
- **有效样本率** ≥ 95%（验证脚本可运行且判定稳定）；
- **低重复率**：语义近重合样本占比 < 5%；
- **性能可区分性**：在固定硬件上，候选策略之间可拉开 ≥ 15% 中位耗时差距；
- **训练增益**：在内部 held-out benchmark 上，Agent 任务成功率提升显著（由训练团队定义阈值）。

---

## 4. 非目标（Non-goals）
1. 不追求生成单一领域（如线性代数）的海量变体；
2. 不在本阶段提供可视化平台；
3. 不绑定某个编程语言（但默认 Python 为主）；
4. 不要求所有任务都必须存在“唯一最优解”。

---

## 5. 参考任务能力拆解（训练能力画像）
从给定 benchmark 抽象出的核心能力：
1. **代码定位能力**：识别入口函数、上下游调用、评测逻辑；
2. **约束理解能力**：从自然语言和 eval 脚本解析 hard constraints；
3. **算法选择能力**：在精度与速度之间折中，选择合适策略；
4. **性能工程能力**：减少 Python 开销、控制分配、利用向量化/缓存；
5. **实验迭代能力**：依据基准反馈快速尝试并回归验证；
6. **边界鲁棒性**：处理极端输入、随机输入、退化输入；
7. **工程交付能力**：保持接口不变，提交可验证成果。

> 结论：合成任务应围绕“**有参考实现可对比 + 强验证 + 时间指标**”这一结构，而不是围绕具体数学对象本身。

---

## 6. 合成数据总体设计

## 6.1 样本结构（仅两部分）
每条合成数据包含：

### A) Instruction
- 问题描述（目标函数、输入输出、约束）
- 可修改范围（允许改哪些文件）
- 禁止事项（禁止改 eval、禁止改接口等）
- 目标（通过正确性校验，并优于 reference 的 median time）

### B) Validation Spec
- 正确性检查规则（断言、容差、性质）
- 性能检查规则（基线、重复次数、统计量）
- 稳定性规则（随机种子、输入分布、超时）
- 失败判定与评分规则

> 不包含参考解与中间思维标注，避免泄露。

## 6.2 任务家族（避免污染）
设计 8 个“能力等价、语义差异大”的任务家族：
1. **小规模数值核函数优化**（但不做特征值）
   - 如：稳定求根筛选、分段多项式批处理、矩阵函数近似。
2. **字符串/字节序列批处理优化**
   - 如：多模式匹配统计、token 频次压缩、rolling-hash 校验。
3. **图算法微内核优化**
   - 如：稀疏图局部传播一步、k-hop 计数、小图连通分量批计算。
4. **动态规划类局部算子**
   - 如：固定窗口编辑距离近似、小规模背包批推断。
5. **几何/空间计算**
   - 如：点集最近邻候选筛、AABB 批量相交测试。
6. **概率统计模拟核**
   - 如：离散采样器、似然批评估、重采样步骤优化。
7. **数据清洗/ETL 核函数**
   - 如：时间戳归一化、缺失值编码、分桶映射批量转换。
8. **解释器式任务**
   - 如：简化 DSL 的执行内核（固定语法，重点在执行效率）。

每个家族都可构建“给定 reference 慢实现 -> 目标函数优化”的模式，保持能力等价。

## 6.3 难度分层
- **L1（入门）**：输入规模小，约束少，主要考察正确性；
- **L2（标准）**：性能门槛明确，随机输入 + 边界输入；
- **L3（进阶）**：非均匀数据分布、多个陷阱 case、较紧时间预算；
- **L4（挑战）**：多目标优化（速度、内存、稳定性）并存。

建议采样配比：L1/L2/L3/L4 = 2/4/3/1。

---

## 7. 数据合成 Pipeline（端到端）

## 7.1 Stage A：任务蓝图生成
输入：任务家族 + 难度级别 + 随机种子。
输出：任务蓝图（接口、约束、数据分布、参考实现策略）。

关键机制：
- 蓝图参数化（规模、容差、超时、样本数）；
- 禁止词与相似度过滤（避免出现参考 benchmark 的关键词、同构结构）。

## 7.2 Stage B：实例化
根据蓝图生成：
- `task.py`（待优化函数骨架 + 慢速参考）
- `eval.py`（校验逻辑）
- `prompt.md`（Instruction）
- `validation.json`（Validation Spec）

注意：对外发布数据仅导出 `Instruction + Validation Spec`。

## 7.3 Stage C：可验证性测试
自动运行：
1. 基线可运行性；
2. 随机种子稳定性（至少 3 个种子）；
3. 判定一致性（多次运行结果一致）；
4. 时间噪声评估（排除方差过大样本）。

## 7.4 Stage D：质量过滤
- 语义去重（embedding + 规则）
- 验证强度过滤（可被投机解轻易绕过的样本剔除）
- 难度校准（过难/过易重采样）

## 7.5 Stage E：发布打包
最终每条记录字段：
- `id`
- `instruction`
- `validation_spec`
- `family`
- `difficulty`
- `tags`（能力标签）

---

## 8. 验证方案设计规范（核心）

每条任务的 Validation Spec 必须包含：
1. **Correctness**
   - 精确断言或数值容差（如 `abs_err`, `rel_err`）；
   - 属性测试（invariant / monotonicity / conservation）；
   - 边界 case 集（空、极值、重复、退化）。
2. **Performance**
   - 基线实现与候选实现同机比较；
   - 统计口径：多次调用取 median；
   - 通过阈值：`median(candidate) <= alpha * median(reference)`，`alpha` 建议 0.85~0.98 依难度配置。
3. **Robustness**
   - 多随机种子；
   - 输入分布漂移（训练分布外 case）；
   - 超时保护。
4. **Anti-cheat**
   - 隐藏测试；
   - 禁止读取 eval 内部答案；
   - 随机化输入长度/顺序以防 hardcode。

---

## 9. 多样性策略（防数据污染）
1. **语义层多样性**：任务家族跨数值、图、文本、模拟、解释器。
2. **接口层多样性**：返回标量/向量/结构体，单函数/双函数协作。
3. **约束层多样性**：精度优先、速度优先、内存优先三类目标轮换。
4. **叙述层多样性**：中英混合、正式说明/业务场景说明两种风格。
5. **反同构检测**：
   - 禁止“dominant eigenvalue / eigenvector / power iteration”等关键词；
   - AST 模板相似度阈值控制；
   - 题面 embedding 相似度低于阈值（如 cosine < 0.88）。

---

## 10. 评分与训练对接

## 10.1 单题评分
- `score = w1*correctness + w2*performance + w3*robustness`
- 默认 `w1=0.5, w2=0.35, w3=0.15`

## 10.2 训练信号
- SFT：使用高分轨迹的“指令-动作摘要-结果”结构；
- DPO/RL：基于同题多候选提交做偏好对；
- Curriculum：按 L1→L4 逐步提升。

---

## 11. 里程碑计划
- **M1（1 周）**：完成 2 个任务家族原型、100 条样本；
- **M2（2~3 周）**：扩展至 5 个家族、1000 条样本；
- **M3（4~6 周）**：全 8 家族、5000+ 样本、上线自动质检；
- **M4（持续）**：根据训练反馈做难度重标与家族扩展。

---

## 12. 风险与缓解
1. **性能噪声大**：固定 CPU 亲和 + 预热 + 中位数统计。
2. **被投机解绕过**：加强 hidden tests 与输入随机化。
3. **样本过于同质**：家族配额 + embedding 去重 + 人工抽检。
4. **验证过慢**：分层验证（快速筛 + 全量复核）。
